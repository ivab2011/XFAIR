# Legal-status labels

DRAFT prepared with Claude for Iva Biscanic's review. Iva's expert sign-off: [ ] approved on ____

Every crosswalk link carries one label for the EU and one for the US. The labels show how
firmly a requirement rests on the source text, so a reviewer can see which findings are law
and which are judgment.

| Label | Meaning | Example |
| --- | --- | --- |
| binding | The source text clearly requires this of this operator. | NIS2 Art. 23(4): early warning within 24 hours |
| interpretive | A binding text applies, but applying it to an AI agent needs a reasoned interpretation. | NIS2 access-control duties applied to an agent's own login |
| voluntary | Guidance or a framework the operator chooses to follow. | NIST CSF 2.0 PR.AA-01 |
| open | No source text settles the question yet. | Who is accountable for an agent's own identity |

Rules for using the labels:

1. A label describes the source, not how important the control is.
2. "binding" with a later application date is written as `binding (applies from YYYY-MM-DD)`.
   EU AI Act high-risk duties for critical infrastructure apply from 2 December 2027.
3. When two reviewers disagree on a label, the link keeps the weaker label and the
   disagreement is recorded.
